# JoyMaaS 文档后台功能详细设计

## 一、定位

JoyMaaS 文档后台不是传统 CMS，也不是照抄 Fern / Mintlify。它是一个把「内容生产 + 数据接入 + AI 辅助 + 审核发布 + 多端分发 + 反馈闭环」串起来的**文档生产运营一体化平台**。

**服务对象**

| 角色 | 在后台里干什么 |
|---|---|
| PM | 写文档、审核、看反馈、决定要不要补文档 |
| 运营 | 组织内容、维护 FAQ、跟踪用户任务完成度 |
| 售前 / 销售 | 查权威口径、把文档给自己的 AI 助手用 |
| 客服 | 查文档答用户问题、反馈用户卡点 |
| 研发 | 维护 OpenAPI、错误码、SDK 示例，看 API 文档同步状态 |
| AI Agent（消费方）| 通过 `.md` / llms.txt / MCP 读取文档 |

**关键原则**

1. 前台操作全部用业务语言：编辑 / 预览 / 提交审核 / 发布 / 下架 / 回滚，不出现 branch、PR、merge、commit。
2. 底层内容采用结构化内容块（block-based），不强绑 MDX。
3. AI 是助手不是主编，人始终掌握发布权。
4. 权限过滤是底线能力，不是加分项。

## 三、10 大功能模块

### 模块一：内容工作台

后台的主入口，PM / 运营的日常工作场所。

#### 1.1 文档列表页

- 支持按分类、状态、负责人、可见性、更新时间、关联模型/接口筛选
- 显示字段：标题 / 分类 / 状态（草稿/审核中/已发布/已下架）/ 可见性（公开/内部）/ 负责人 / 更新时间 / 关联数据源 / 健康度评分
- 批量操作：批量下架、批量重新分发、批量交给 AI 检查
- 快捷入口：新建空白文档、从模板新建、从 AI 生成初稿、从 DocBot 录制生成、从 OpenAPI 生成 API Reference
- 全站搜索：跨标题、内容、组件、元信息

#### 1.2 组件化编辑器

- **块级编辑**：类 Notion 的 `/` 斜杠菜单插入组件，不写 Markdown 语法
- **左侧**：文档大纲，可拖拽调整顺序
- **中间**：编辑区，每个内容块可独立操作（复制/删除/移动/AI 改写）
- **右侧**：属性栏 + AI 助手侧栏（可折叠）
- 支持双列布局：编辑 + 实时预览
- 自动保存草稿（每 30 秒）
- 撤销 / 重做
- 快捷键体系

#### 1.3 AI 助手侧栏

嵌在编辑器右侧，随时可用：

- 续写当前段落
- 改写选中内容（正式 / 简洁 / 更适合新手 / 更适合开发者）
- 生成摘要 / 大纲
- 生成 FAQ
- 检查当前文档缺漏
- 检查术语一致性
- 从数据源生成参数表 / 错误码表 / 请求示例
- 翻译（中英）
- 把开发文档改写成用户视角文档
- 询问式生成：「帮我加一段说明 stream 参数的注意事项」

#### 1.4 文档元信息

每篇文档必须填的元信息（这些数据后续会喂给 llms.txt、搜索索引、权限引擎）：

| 字段 | 用途 |
|---|---|
| 标题 | 页面标题、导航、搜索、llms.txt |
| 描述 | 摘要，喂给 AI 和搜索 |
| 分类 | 快速开始 / API Reference / 场景指南 / 排障 / 计费 / 内部 |
| 标签 | 关联模型、能力、场景 |
| 可见性 | 公开 / 登录后可见 / 内部 / 售前 / 研发 |
| 是否允许 AI 读取 | 是否进 llms.txt 和 MCP |
| 关联数据源 | 关联的 OpenAPI endpoint / 模型 / 错误码 / PRD |
| 负责人 | 谁维护，反馈信号自动派给这个人 |
| 更新周期 | 无 / 月 / 季 / 变更触发 |
| 优先级 | 首页推荐 / 常用 / 长尾 |

#### 1.5 内容模板库

预置模板，避免每次从零开始：

- Quickstart 模板（含步骤条、代码 Tab、下一步推荐）
- API Reference 模板（Endpoint + 参数表 + 请求/响应示例 + 错误码）
- 场景方案模板（客服 / 知识库 / Agent 接入 / 内容生成）
- 错误排障模板（症状 + 原因 + 排查步骤 + 相关文档）
- 计费说明模板（计费方式 + 公式 + 示例 + 优化建议）
- 模型接入模板（模型能力 + 参数 + Prompt 示例 + 成本）

模板本身可以被编辑，也支持团队自建模板。

### 模块二：文档组件库

不允许自由塞 React 组件，只允许后台白名单里的**文档组件**。每个组件都必须有 4 种形态：**编辑形态、Web 展示、Markdown 导出、AI 语义解释**。

#### 2.1 组件白名单（6 大类）

**A. 基础内容组件**
- 标题（H1-H4）
- 段落
- 有序 / 无序列表
- 表格
- 分割线
- 引用块
- 图片（含描述文本，用于 AI）
- 视频 / GIF（含文字备用说明）

**B. 开发接入组件**
- 单代码块（含语言、行高亮、复制按钮）
- 多语言代码 Tab（Python / Go / Java / cURL / Node）
- 环境变量块
- SDK 安装块
- 请求 / 响应示例对
- 一键复制完整示例

**C. API Reference 组件**（多数由 OpenAPI 自动生成）
- Endpoint 卡片
- 请求参数表
- Header 表
- Body Schema
- Response Schema
- 错误码表
- Try it / Playground 入口
- SDK snippets

**D. MaaS 专属组件**
- 模型能力引用卡（引用产品前台元数据，不重复展示）
- 模型选择指引
- Prompt 示例块
- 流式返回示例
- Function Calling 示例
- 多轮对话结构
- Agent 接入示例（Cursor / Claude Code / 内部 Agent）
- 成本估算说明
- 生产实践 Checklist

**E. 提示与权限组件**
- Tip / Note / Warning / Error
- Limitation（能力限制）
- Beta（灰度/内测）
- Deprecated（已废弃，含替代方案）
- Cost Notice（费用提醒）
- Internal Only（内部可见块，一定要有权限标记）

**F. AI 友好组件**
- Copy as Markdown 按钮
- 查看 .md 入口
- llms.txt 入口
- Ask AI 触发块
- 引用来源（给 AI 引用用）
- MCP 入口（后置）
- AI 摘要块（页面顶部给机器读的短摘要）

#### 2.2 组件规范定义

每个组件在后台里都要维护一份规范表（研发按这个开发）：

| 字段 | 说明 |
|---|---|
| 组件名 | 唯一标识 |
| 中文名 | 展示 |
| 用途 | 一句话 |
| 编辑形态 | 后台里怎么填 |
| Web 形态 | 页面上长什么样 |
| Markdown 导出 | 转成什么样的 md |
| AI 语义 | 是 warning 还是 note 还是 example |
| 可见性维度 | 是否支持 InternalOnly 标记 |
| 数据源 | 是否绑定 OpenAPI / 模型元数据 / 错误码 |
| 是否可 AI 生成 | AI 助手能不能自动生成 |

#### 2.3 组件版本管理

组件本身有版本。组件升级时：
- 后台会提示「XX 组件已升级，是否将现有页面统一升级」
- 支持批量升级 / 逐页升级
- 老版本保留兼容渲染，避免线上文档突然崩

### 模块三：数据源接入

文档不再是人工抄写的二手信息，而是从产品自身接入的一手事实。

#### 3.1 模型元数据订阅

- 从 Leah 正在做的**模型接入一体化后台**订阅
- 用于：模型引用卡、模型清单、llms.txt 里的模型枚举
- 只订阅，不重写；文档站不做展示，只做「关于这个模型怎么用」的集成说明
- 变更监听：模型上线 / 下线 / 改价 / 改能力 → 触发受影响文档识别

#### 3.2 OpenAPI Spec 接入

- 支持导入 / 定期同步 OpenAPI 3.x
- 从 spec 自动生成：Endpoint 卡片、参数表、请求/响应 schema、错误码骨架、多语言 SDK 示例初稿、Playground 配置
- 生成的内容进入草稿，**不自动发布**
- Spec 变更 → 显示 diff → 生成变更工单 → 相关文档标记「待更新」

#### 3.3 错误码库

- 独立维护错误码：code / 中文说明 / 原因 / 排查步骤 / 相关文档
- 文档里通过组件引用，改错误码库文档跟着变
- 支持从日志/客服工单反哺（哪些错误码高频命中）

#### 3.4 内部 PRD 与知识

- 打通 JoySpace，可以把 PRD、内部规范、竞品分析加入 AI 生成的上下文
- 不直接发布，仅作为 AI 生成的参考素材
- 权限：内部内容仅内部可见，不能带到公开文档里（AI 生成时明确隔离）

#### 3.5 计费与价格

- 从内部计费系统订阅价格、单位、变更时间
- 组件引用，改价自动传播
- 内部版可以显示折扣空间，外部版只显示 List Price

#### 3.6 控制台操作录制（DocBot 复用）

- 录制控制台操作 → 生成操作型文档初稿（创建 Key、开通模型、查看日志）
- 支持标注不确定字段（价格、权限、可用范围），要人工填
- 输出成组件化内容进入文档草稿

### 模块四：AI 能力中心

AI 不是零散功能，是一个独立模块，覆盖文档全生命周期。

#### 4.1 架构生成

从 0 到 1 阶段用得最多：

- 输入：竞品文档、旧帮助中心、PRD、控制台路径、API 列表、用户搜索词、客服问题
- 输出：新版目录草案 + 每篇文档的说明 + 负责人 + 数据源 + 优先级
- 支持迭代：给 AI 反馈「太偏运营视角，需要更开发者视角」

#### 4.2 内容生产

- 生成 API Reference 初稿（基于 OpenAPI）
- 生成 Quickstart（基于 API + 控制台路径）
- 生成场景方案（基于 PRD + 竞品）
- 生成错误排障（基于错误码 + 客服工单）
- 生成 Prompt 示例（基于模型能力 + 典型任务）
- 生成多语言 SDK 示例
- 生成 FAQ（基于 Ask AI 高频问题）

#### 4.3 内容改写与优化

- 把开发文档改写成用户视角
- 长文档拆解为组件
- 统一术语（术语库匹配）
- 简化 / 正式化 / 面向不同角色改写
- 中英翻译（保留代码不动）
- 结构梳理（自动加 H2/H3、拆段落、加下一步推荐）

#### 4.4 质量检查

发布前 AI 自动扫，形成检查清单：

- 参数是否和 OpenAPI 一致
- 错误码是否覆盖完整
- 代码示例是否语法合法
- 是否缺少费用提醒 / 权限说明 / 下一步推荐
- 是否有敏感信息（内部价格、员工信息、灰度能力）泄漏到公开文档
- 术语是否一致
- 链接是否有效
- 是否有已废弃 API 的引用

#### 4.5 变更传播

模型元数据、OpenAPI、错误码、价格变了：
- AI 找出所有受影响文档
- 生成修改建议（对哪个组件、改成什么）
- 进入审核队列
- 人审核后发布，不自动上线
- 保留「哪些没改成功、哪些跳过」的清单

#### 4.6 反馈闭环生成

- 零结果搜索 → 判断是「文档缺失」还是「检索问题」
- 文档缺失 → AI 基于已有数据源生成草稿 → 进审核队列
- 检索问题 → 给出「已有 XX 文档，但没被搜到」提示，触发关键词补充或搜索优化
- 用户反馈「没帮助」→ AI 分析问题、生成改进建议

#### 4.7 AI 能力的边界（重要）

- 价格 / 权限 / 灰度状态 / 模型能力边界 → 不允许 AI 编，只能引用数据源
- 未知字段 → 生成占位符「__待填__」，标黄提示
- 内部内容 → 明确隔离，AI 生成公开文档时读不到内部素材
- 引用来源 → AI 生成的每段内容标注来源（PRD / OpenAPI / 错误码 / 已发布文档）

### 模块五：审核与发布中心

**前台绝不出现 branch / PR / merge**，只有业务化的发布流。

#### 5.1 发布状态机

```
┌──────┐    提交审核    ┌──────────┐   驳回    ┌──────┐
│ 草稿 │ ─────────────> │ 待审核    │ ────────> │ 草稿 │
└──┬───┘                └────┬─────┘           └──────┘
   │                         │ 通过
   │ 直接保存                │
   │                         ▼
   │                    ┌──────────┐
   │                    │ 待发布    │
   │                    └────┬─────┘
   │                         │ 发布 / 定时 / 灰度
   │                         ▼
   │                    ┌──────────┐   下架    ┌──────────┐
   │                    │ 已发布    │ ────────>│ 已下架    │
   │                    └────┬─────┘           └────┬─────┘
   │                         │ 回滚                 │ 重新发布
   │                         ▼                      │
   │                    ┌──────────┐               │
   │                    │历史版本   │ <─────────────┘
   │                    └──────────┘
   ▼
（可删除，保留操作日志）
```

#### 5.2 审核队列

- 待审核文档统一进队列
- 按类型分组：新建文档、内容修改、AI 生成草稿、变更传播、零结果补文档
- 每条显示：标题、类型、提交人、提交时间、优先级、影响范围
- 审核员操作：查看 diff、预览、通过 / 驳回 / 打回修改
- 支持多级审核（内容审核 + 权限审核 + 研发审核）
- 支持并行审核：内容 PM 审、API 研发审、权限管理员审，全部通过才可发布
- 审核意见留痕

#### 5.3 审核规则引擎

按内容类型自动路由到不同审核人：

| 内容类型 | 审核人 |
|---|---|
| API Reference 变更 | 对应研发 + PM |
| 计费说明 | 计费 PM + 财务 |
| 内部可见内容 | 权限管理员 |
| 模型能力变更 | 算法 / 模型 PM |
| 首页 / Quickstart | 内容负责人 + 组长 |
| 长尾文档 | 单人审核 |

#### 5.4 预览

- 每次修改都能生成预览链接
- 预览时可切换：桌面 / 移动、公开视角 / 内部视角
- 可分享预览链接给非编辑人员看（有时效）
- 预览包含 Markdown 版本、llms.txt 差异预览

#### 5.5 发布形式

- **立即发布**：审核通过后一键上线
- **定时发布**：约定时间点自动上线（配合产品发布节奏）
- **灰度发布**：先对内部账号可见，验证后再全量
- **分环境发布**：预发 → 生产

#### 5.6 回滚与历史

- 每次发布产生一个历史版本
- 版本列表显示：版本号 / 发布人 / 发布时间 / 修改摘要
- 支持一键回滚到任意历史版本
- 回滚也走审核（避免误操作）
- 版本 diff 可视化对比

#### 5.7 下架

- 支持整篇下架 / 部分组件下架
- 下架页面自动 302 到「已下线说明页」或替代文档
- 下架不删除内容，保留在历史区
- 下架也进入审核，避免误操作

### 模块六：多端输出

同一份内容源，产出多种消费形态。

#### 6.1 Web 页面

- 独立文档站（新版），不寄生在京东云帮助中心
- Notion 风格 / 现代文档站视觉
- 导航、搜索、面包屑、下一步推荐、目录锚点
- 支持内部登录后看到内部内容

#### 6.2 页面 .md

- 每篇文档自动生成 `.md` 版本
- URL：`/quickstart` → `/quickstart.md`
- 内容规则：
  - Tabs 展开为多个 H3 段落
  - Callout 转为 `> [!WARNING]` 语义
  - Playground 转为「Endpoint + 示例请求 + 参数说明」
  - 模型引用卡展开为「模型 ID / 上下文长度 / 价格 / 能力标签」
  - Internal Only 内容按访问身份决定是否输出

#### 6.3 llms.txt

- 全站自动生成，发布触发更新
- 每篇文档一行：`- [标题](url.md): 描述`
- 按分类分组
- 只包含「已发布 + 允许 AI 读取 + 公开」文档
- 内部 llms.txt 单独一份，供内部 AI 使用

#### 6.4 搜索索引

- 结构化索引，不是全文糊在一起
- 支持按分类、组件类型、标签检索
- 搜索无结果自动记录，进反馈闭环
- 支持同义词、错误拼写、开发者关键词映射

#### 6.5 内部 AI 数据源

- 售前 / 客服 / 运营的 AI 助手订阅内部版内容
- 权限隔离：内部 AI 看内部+公开，外部 Agent 只看公开
- 通过 API 或数据推送方式提供

#### 6.6 MCP Server（后置，P2）

- 让 Cursor / Claude Code / 内部 Agent 直接连
- 提供：search / fetch / list_categories 等基础工具
- 鉴权：外部匿名（只返回公开）/ 内部 Token（返回内部）

#### 6.7 OpenAPI 分发

- 文档站顺带分发权威 OpenAPI spec
- 供第三方 SDK 生成器使用
- 版本化，历史可查

### 模块七：权限与可见性

不是「登录后可见」这么简单，是一套内容级 + 字段级的过滤引擎。

#### 7.1 可见性维度

**内容级**

| 可见性 | 谁能看 |
|---|---|
| 公开 | 所有人、外部 Agent |
| 登录后可见 | JoyMaaS 用户 |
| 客户级 | 特定客户白名单（如私有化客户）|
| 内部通用 | 京东内部员工 |
| 内部售前 | 售前 / 销售 |
| 内部研发 | 研发 |
| 草稿 | 仅编辑者和审核人 |

**字段级 / 组件级**

- 一篇公开文档里可以有 `<InternalOnly>` 组件
- 组件内容仅在内部视角下渲染
- 外部访问、公开 llms.txt、外部 MCP 全部过滤掉

#### 7.2 用户角色

| 角色 | 权限 |
|---|---|
| 阅读者 | 只看后台数据，不改内容 |
| 编辑者 | 写文档、提交审核 |
| 审核者 | 审内容 |
| 管理员 | 权限、角色、组件、模板管理 |
| 数据源管理员 | 维护 OpenAPI / 错误码 / 元数据订阅 |
| AI 管理员 | 配置 AI 生成规则、Prompt、边界 |

#### 7.3 分发目标权限矩阵

同一篇文档，出到不同通道时的可见规则：

| 通道 | 公开内容 | Internal Only 块 | 内部专属文档 |
|---|:---:|:---:|:---:|
| 外部 Web | ✅ | ❌ | ❌ |
| 外部 .md | ✅ | ❌ | ❌ |
| 公开 llms.txt | ✅ | ❌ | ❌ |
| 外部 MCP | ✅ | ❌ | ❌ |
| 内部 Web（登录） | ✅ | ✅ | ✅ |
| 内部 .md | ✅ | ✅ | ✅ |
| 内部 llms.txt | ✅ | ✅ | ✅ |
| 内部 AI 数据源 | ✅ | ✅ | ✅ |

#### 7.4 敏感信息检查

发布前自动扫，命中要人工确认：
- 手机号、邮箱、员工号
- 内部系统链接、内网 IP
- 内部代号 / 项目名
- 价格 / 折扣数值（是否应该是 Internal Only）
- 灰度 / 内测能力标记

### 模块八：反馈闭环

把用户行为转成文档改进任务。

#### 8.1 采集的信号

| 信号 | 采集方式 | 用途 |
|---|---|---|
| PV / UV / 停留时间 | 埋点 | 内容健康度 |
| 搜索词 | 搜索框 | 用户需求分布 |
| 搜索无结果 | 搜索框 | 文档缺口 |
| 复制代码 | 代码块按钮 | 高价值示例识别 |
| Copy as Markdown | 组件按钮 | 用户在给 AI 用 |
| Playground 请求失败 | Playground | 参数说明有问题 / 产品问题 |
| Ask AI 会话 | 站内 AI | 用户真实问题 |
| Ask AI 满意度 | 点赞 / 点踩 | 回答质量 |
| 页面反馈（有帮助/没帮助）| 页脚组件 | 内容质量 |
| 文字反馈 | 页脚组件 | 具体改进建议 |
| LLM Bot 访问 | User-Agent | 哪些页面被 AI 常读 |

#### 8.2 缺口识别

原始信号 → 分类：

**A. 文档缺失**
- 零结果搜索 & 无相似文档
- Ask AI 高频问题 & 现有文档不能答
- → 自动生成草稿进审核队列

**B. 文档不清**
- 停留异常长 + 有反馈
- Ask AI 满意度低
- → 标记「待改进」，推给负责人

**C. 检索问题**
- 零结果搜索 & 有相似文档
- → 添加同义词 / 关键词 / 标签

**D. 产品问题**
- Playground 请求失败率高
- 特定错误码集中出现
- 用户反复问同一个功能
- → 推给对应产品线，不进文档修改队列

**E. 内容分层错位**
- 内部信号频繁问外部文档没有的内容
- → 提示是否要提供公开说明

#### 8.3 待办生成

反馈信号统一进入「文档待办队列」：

- 类型：补文档 / 改文档 / 加关键词 / 推产品 / 推研发
- 优先级：影响用户数量、频次、失败率
- 负责人：默认关联文档负责人，可转派
- 状态：待处理 / 处理中 / 已完成 / 已忽略
- 反哺：处理完的待办，跟踪相关信号是否下降

#### 8.4 自动写草稿动线

零结果搜索的完整闭环：

```
用户搜「流式返回」
   ↓
搜索系统：0 命中，且没有相似文档
   ↓
后台记录：关键词 / 搜索次数 / 用户上下文
   ↓
达到阈值（如 20 次 / 一周内）
   ↓
AI 拉数据源：OpenAPI 里的 stream 参数 / 错误码 / 内部 PRD
   ↓
生成《流式返回使用指南》草稿
   ↓
进入审核队列，标注「零结果驱动生成」
   ↓
PM 审核 → 补充 → 发布
   ↓
观察后续搜索是否命中、停留时间、满意度
```

## 八、诚实边界

1. **AI 生成质量取决于数据源质量**：如果 OpenAPI spec 不齐、PRD 散乱、错误码库不全，AI 起草效果会差。这块前置依赖要跟产品/研发对齐。
2. **权限过滤有落地成本**：字段级 InternalOnly 组件在 P0 只保留组件语义，完整过滤引擎在 P1 落地。
3. **变更传播容易出错**：自动改文档风险高，P1 只做「提示」不自动执行，P2 才谨慎放开。
4. **反馈闭环需要用户量**：初期用户少时，零结果搜索、停留时间信号量不足，无法自动补文档。这时 AI 生成的价值主要在初始文档构建。
5. **和现有帮助中心的关系**：默认「新站独立 + 旧站保留跳转」，具体切换节奏要跟老板对齐。

## 九、给老板的一句话

> 这不是重做帮助文档。这是把「文档」这层，变成 JoyMaaS 用户体验和内外协同的产品化平台——**内容 AI 起草、组件化沉淀、数据源驱动、审核发布规范、多端可读、内外可服务、行为可反哺**。它承担的是用户能不能顺畅用起来的关键一环。
