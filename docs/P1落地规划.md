# JoyMaaS 文档系统 P1 落地规划

> P0 交付了双通道文档站的底座（前台 + 后台 + Agent 三件套 + OpenAPI 自动生成 + 部署上云）。**P1 补足产品构想里"文档 = 增长杠杆"的关键证据**：消费侧 AI 体验（Playground + Ask JoyMaaS） + 智能运营层最小闭环（零结果搜索 → 自动写文档）。执行者：Sonnet。

---

## 0. 一句话目标

**让 JoyMaaS 文档从"更好的帮助中心"升级为"半个产品"**，具体做到：

1. **读到即可试** —— Playground 组件让 API 参考页能点一下真跑
2. **问即可答** —— Ask JoyMaaS 内嵌问答，用户在文档里直接问 AI
3. **文档自我进化** —— 用户问不出来的问题 → 自动写草稿 → 进审核队列 → PM 审完上线
4. **写作大幅提效** —— AI 帮写从 4 能力扩到 6 能力 + prompt 精调 + 交互重做
5. **视觉/交互到位** —— 前台后台一次性打磨，能上老板级演示台面

## 3. 技术选型（钉死）

### 3.1 Playground

- **前端组件**：`apps/site/src/components/mdx/Playground.tsx`，白名单，MDX 里 `<Playground endpoint="chat-completions" defaultModel="..." />`
- **后端代理**：`apps/backend/src/routes/playground.ts` → `POST /api/playground/run`，参数走 Joybuilder，SSE 流式回流
- **临时 Key 策略**：前端不落 Key；后端用 `.env` 里的服务级 Key，加简单频控（IP 维度 10 req/min）
- **模型清单**：读 `content-repo/openapi/openapi.yaml` 的 `x-models` 扩展字段

### 3.2 Ask JoyMaaS（长上下文轻量版）

- **不建向量库**：直接把 `llms-full.txt` 塞进模型 system prompt。10 篇文档 30-60KB，Joybuilder Pro 上下文窗口够
- **后端**：`apps/backend/src/routes/ask.ts` → `POST /api/ask`，SSE 流
- **前端**：`apps/site/src/components/AskWidget.tsx`，右下角浮球 + 抽屉 + SSE 渲染
- **profile 隔离**：内部页面用 `llms-full-internal.txt`（含 InternalOnly），外部页面用 `llms-full.txt`（过滤后）
- **升级路径**：内容扩到 30+ 篇后再评估是否要上真 RAG（向量库 + embedding），P1 不做

### 3.3 智能运营层 POC（零结果 → 自动写）

- **信号采集**：`ask_result_none` 事件（Ask 里 AI 答"我不知道"时打） + pagefind 零命中事件
- **聚类**：简单 embedding + cosine 相似度合并（Joybuilder 若有 embedding 接口用之，无则用 keyword TF-IDF 兜底），阈值 > 0.85 合并
- **触发条件**：同一 query 簇 ≥ 3 次 / 7 天
- **生成**：Joybuilder Flash + prompt 模板，产 mdx 草稿（title/frontmatter/结构）
- **入队**：git 建 `auto/gen-YYYYMMDD-<hash>` 分支 → push → 调 Coding API 建 MR，label = `auto-generated`
- **后台改造**：审核队列列表每行加一个 badge（`PM` / `工程师` / `机器`），机器 PR 单独筛选

### 3.4 编辑体验升级

- **AI 会话史**：新表 `ai_sessions`（sessionId / docSlug / userAction / prompt / response / createdAt）
- **重生成**：会话 UI 里每条 AI 输出旁一个"重新生成"按钮
- **全流式**：complete / generate / audit 三个能力从"一次返回"改成 SSE 流
- **两个新能力**：
  1. `POST /api/ai/gen-params-from-openapi`：输入 endpoint slug，输出一段 `<Params>` MDX
  2. `POST /api/ai/gen-frontmatter`：输入正文，输出 title/description/category/tags 建议

### 3.5 视觉/交互打磨

- **前台**：已有 `apps/site/DESIGN_TOKENS.md`，本轮不动 tokens，只打磨四个具体页面
- **后台**：本轮**新增** `apps/admin/DESIGN_TOKENS.md`，风格对齐前台（同一套色板 + 字号 + 间距），字体和 Stripe 后台风格保留
- **交互细节**：见 §11

## 5. 数据模型变更

### 5.1 新增表

```sql
-- Ask 会话（用于零结果信号 + 用户反馈）
CREATE TABLE ask_sessions (
  id INTEGER PRIMARY KEY,
  session_id TEXT NOT NULL,           -- 前端生成的 uuid，同一次抽屉打开共用
  query TEXT NOT NULL,
  answer TEXT,                        -- AI 全文回答（异步补写）
  result_none INTEGER DEFAULT 0,      -- 1 = AI 答"我不知道"
  useful INTEGER,                     -- NULL / 1 / 0（用户点赞踩）
  audience TEXT NOT NULL,             -- 'external' | 'internal'
  page_slug TEXT,                     -- 提问时所在页面
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- AI 写作会话历史
CREATE TABLE ai_sessions (
  id INTEGER PRIMARY KEY,
  session_id TEXT NOT NULL,
  doc_slug TEXT NOT NULL,
  action TEXT NOT NULL,               -- 'rewrite'|'complete'|'generate'|'audit'|'gen-params'|'gen-frontmatter'
  prompt TEXT,
  response TEXT,
  model TEXT,
  latency_ms INTEGER,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 文档缺口候选（智能运营层 POC）
CREATE TABLE doc_gaps (
  id INTEGER PRIMARY KEY,
  cluster_hash TEXT UNIQUE,           -- 聚类后的语义哈希
  representative_query TEXT NOT NULL, -- 簇内代表 query
  query_count INTEGER DEFAULT 1,
  first_seen TIMESTAMP,
  last_seen TIMESTAMP,
  status TEXT NOT NULL,               -- 'pending' | 'drafting' | 'mr-created' | 'merged' | 'dismissed'
  mr_iid INTEGER,                     -- 生草稿后 Coding MR iid
  draft_slug TEXT,                    -- 生成的文档 slug
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 5.2 现有表改动

`review_tasks` 加一列：

```sql
ALTER TABLE review_tasks ADD COLUMN source_kind TEXT DEFAULT 'pm';
-- 值：'pm' | 'engineer' | 'auto'   （auto = 智能运营层生的机器 PR）
```

现有数据回填 `pm`（Web 提交默认）或 `engineer`（webhook 来的默认）。

## 7. 智能运营层 POC 实现（W16）

### 7.1 采集

已有 `ask_sessions` 表（resultNone 字段）+ pagefind 零命中埋点（`search_no_result` 事件）。W16 不再新加采集。

### 7.2 聚类（`services/cluster.ts`）

**定时任务**：backend 起一个 setInterval 每 6 小时跑一次。

```
1. 读近 7 天 ask_sessions where result_none=1 union search_no_result events
2. 对每条 query 算 embedding（Joybuilder embedding 接口；无则回退 TF-IDF 向量）
3. 对未聚类 query，两两算 cosine，> 0.85 合并簇
4. 每个簇算代表 query（簇内出现次数最多的）
5. 写入/更新 doc_gaps 表（cluster_hash 用簇内首个 query 的 sha256 前 16）
6. 满足 query_count >= 3 && status=pending 的 → 触发生草稿
```

**边界**：
- 冷启动没数据时也要跑通，不报错
- Joybuilder embedding 失败时回退 TF-IDF，日志告警
- 聚类是尽力，不追求完美

### 7.3 生草稿（`services/auto-gen.ts`）

对 `status=pending && query_count>=3` 的 gap：

```
1. 从 llms-full.txt + 用户 query 拼 prompt（backend/src/prompts/auto-doc-draft.md）
2. 调 Joybuilder Flash 生成 mdx 全文（含 frontmatter）
3. 起分支 auto/gen-<date>-<clusterHash>
4. 写文件到 content-repo/content/guides/auto-<slug>.mdx（category=guides 默认）
5. commit + push
6. 调 gitlab.MergeRequests.create()，target=main，labels=['auto-generated']
7. 更新 doc_gaps status='mr-created'，写 mr_iid
```

**Sonnet 注意**：
- 生草稿失败不删 gap 记录，status 保持 pending，下轮重试
- 频率：一次任务最多生 3 篇，避免 AI 卡住批量刷屏
- MR 描述里必须写：`本 MR 由智能运营层自动生成，触发信号：X 次用户搜索"<query>"未命中`

### 7.4 后台队列改造（`ReviewView.vue`）

- 每行加 badge：PM（蓝）/ 工程师（绿）/ 机器（紫）
- 顶部加筛选下拉：全部 / PM / 工程师 / 机器
- 机器 PR 的详情页多一个块："触发信号：X 次搜索 <query>"

## 13. Sonnet 执行守则

沿用 P0 §14 十条，另加 P1 特有：

1. **不问"要不要顺便做 X"**。范围钉死在 §2。
2. **不写占位代码**。每次提交端到端能跑。
3. **不造名词**。定位、组件名、文案照抄本文档。
4. **不写多余注释**。README 只写"怎么跑起来"。
5. **每周交付 `weekly-<n>.md`** 到 `docs/weekly/`。含完成 / 未完成 / 阻塞。
6. **Playground / Ask 后端不引 langchain**，直连 Joybuilder，一个能力一个 prompt 文件。
7. **前端不接触任何 API Key**。Playground 一切走后端代调。
8. **`services/cluster.ts` + `services/auto-gen.ts` 必须写单元测试**，覆盖率 > 70%。
9. **视觉打磨照 DESIGN_TOKENS 走，不发明新色**。前台已有 tokens，后台 W15 立完就冻结。
10. **AI 能力上线前必须 dogfooding** —— Sonnet 自己用当周新 AI 能力改 3 篇文档，产出报告写进 weekly。
11. **智能运营层 POC 不追求真信号**——W16 允许人工灌假 query 演示端到端。真信号跑起来是 W17 后的事。
12. **提交作者身份**：所有 commit 用 `liangyuanwen.1 <liangyuanwen.1@jd.com>`，PM 视角。工程师视角的 commit 由 Sonnet 用另一个 identity（如 sonnet-agent）以模拟双通道，可在演示时切换。
